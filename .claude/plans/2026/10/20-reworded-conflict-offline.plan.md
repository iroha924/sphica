## 方針

- 置き場所は `server/evals/conflict/`。出荷物には入らない
- 時点: 「2026-10-20 に固定した記録に、10 月の依頼を当てた評価」とする。過去の時点の記録には戻さない
- 隔離: 検索は持ち主の DB を `VACUUM INTO` で scratchpad に写したもの（コミットしない、sha256 を控える）と一時 HOME だけで流し、本番の配信と capture を呼ばない
- 記録の母集団: 写しの sphica のプロジェクトで `deliverableIds` に入る、dont の決定と rejected option を持つ記録。unit id と option id の列と sha256 で固定する
- 分割: 依頼を作る前に、unit 単位で seed で tune と held-out に分ける。同じ unit の dont・option・日英・対応する紛らわしい依頼は同じ側。普段の依頼はセッション単位で分ける
- 反する依頼（positive）: seed で 60 対象（dont 30、rejected option 30）。対象ごとに日本語と英語を 1 つずつ（120 件）、うち 1/4 は上書きを明示する依頼
- 紛らわしい依頼（hard negative）: 60 件。却下案の無害な話題、否定、選んだ案と却下案の語が混ざる依頼
- 書き手: positive と hard negative を Codex と Claude が半分ずつ書く。渡すのは記録の text・why・option の文・scope・reconsider_when で、alias と検索結果は渡さない
- 普段の依頼: sphica、[2026-10-01T00:00+09:00, 2026-10-20T00:00+09:00)、両ホストの owner の session_message。AskUserQuestion の答えと、`sample.ts` が見分ける通知・注入文を除く。短い返事は含める（プロンプトの配信が実際に走る依頼のため）。seed で 400 件、除いた件数を残す。候補の無い依頼も分母に残す
- ラベル
  - 衝突の集合: 依頼された変更が、その dont の決定か rejected option（と却下の理由）に反する記録。生成元と、同じ衝突を裏付ける別の記録を含む。positive の再現率はこれで数え、どれか 1 件が表示されれば拾えたとする
  - 関連の集合: 話題として関係する記録。普段の依頼の「無関係な候補」と hard negative の報告に使う
  - 上書きの有無は別のラベル
  - 合成の依頼は、書き手と別のモデル（Codex の書いた分は Claude、Claude の書いた分は Codex）が検索結果を見ずに全件を確かめ、採る・直す・捨てるを決め、ラベルを検索を流す前に確定する。反すると言えない positive と、反してしまう hard negative は捨てる（生成したときの種類を正解として強制しない）。直した文は、直した側と別のモデルがもう一度確かめる。確認者は labels の `review`（cross_model）に残す
  - 確認する側は、依頼がほかの対象の記録にも反するかも見て、衝突の集合へ足す。衝突の集合は「今回確かめた集合」で、網羅したとは言わない
  - 普段の依頼に出た候補は、Claude と Codex が別々に関連 / 無関係を付ける。割れたものは、両者に相手の判定と理由を同じ資料で 1 回だけ見せて見直させ、それでも割れたものは「判定不能」。初回の一致数と見直し後の一致数を公開 JSON に残す
- 拾い方
  - B0: `namedRecords` そのまま（固定の比較）
  - B1a: B0 に、alias の語が依頼に `namedRecords` と同じ語の境界で含まれる記録を足す
  - B1b: 同じく、`terms()` の語分割で一致する記録を足す
  - B2: B0 に、`searchUnits` の結果を dont の決定と rejected option を持つ記録に絞り、B0 と重ならないものを足す。取得上限は tune で 5 / 10 / 20 から選ぶ。rank の閾値は使わない
  - B1・B2 の絞り込みの条件は共通。並べ方は B0 を先に、足した候補を後に。併用（B0+B1+B2）も比べる
  - tune では信号を分けても比べる: rejected option の一致、chosen option だけの一致、path・symbol、alias だけ、本文の語、option の `terms()` 版
- 表示の計算: 出荷コードを変えないため、`onPrompt` の切り方を評価側に写す。B0 の候補では、一時 DB で実際の `deliver` を呼んだ表示と一致することをテストで確かめる（文字数の境界、長い先行候補、AI の採用の印を含む）
- 数えるもの（held-out、日英別、上書きの有無別）
  - positive: 候補に入る / 上位 3 に入る / 表示される割合。落ちた理由を、検索に候補が無い・取得上限で切られた・順位で落ちた・文字数で落ちたに分ける
  - B0 との差: 同じ依頼で改善した件数と悪化した件数
  - 普段の依頼: 無関係な候補が 1 件以上出た割合。補助として、判定不能の候補を無関係とみなした割合も出す（判定の規則には使わない。結論が変わるなら、判定不能の扱いに依存すると結果に書く）
  - hard negative: 候補が出た割合（無関係の率とは数えない）
  - 全割合に件数・分母・Wilson 95% 区間。同じ unit の日英や同じセッションの依頼を、独立した実利用の証拠として読まないと書く
- 判定の規則（下の叩き台の値を、評価する側がラベル付けの前にそのまま固定する）
  1. 保留（最初に見る）: held-out で、持ち主が捨てた後の positive がどちらかの言語で 24 件未満、普段の依頼が 160 件未満、または判定不能がどれかの群で 10% を超える。判定不能は分母から除き、件数を出す
  2. 進む候補あり: ある方式が、held-out の positive で表示される割合が 60% 以上かつ B0 より 20 ポイント以上高く、B0 が表示できて新しい方式が落とした件数が 0、日英どちらでも B0 を下回らず、普段の依頼で無関係な候補が出た割合の Wilson 上限が 10% 以下
  3. それ以外は「今回の方式では進めない」。未達の原因を語彙・絞り込み・順位・予算に分け、次に比べる信号を書く
- 公開するもの: 評価コード、持ち主の発言と関係なく作ったテストの fixture、ID・ハッシュ・分割・パラメータ・候補 ID・ラベル・集計値。合成の依頼の本文は持ち主の記録の言い換えを含むので公開しない（ID とハッシュだけ）。公開 JSON は許可したキーだけを書き出し、本文が混ざらないことをテストで確かめる
- 結果は「持ち主の確認を経ない、モデルの確認によるオフライン評価」と明記し、モデル別の初回一致率、直した・捨てた・判定不能の件数、書き手別の成績を並べる
- ほかの計測との切り分け: 依頼の作成とラベル付けで本番のログに残るセッション（この計画の会話、codex exec の実行）の ID と期間を控える。#353 は分子と分母の両方から除いた値も、#218 は止めた呼び出しのうち評価のセッションのものを別に、どちらも元の集計と並べて出せるようにする
- 結果は #260 にコメントする（文面は持ち主の承認の後）

## 採った案と棄却した案

- 採用: 段階 1 だけをこの計画にする。棄却: 3 段を 1 つの計画にする（段階 2 の置き場所が schema に響き、段階 1 の結果で要否が変わる）
- 採用: 表示まで（予算で切った後）測る。棄却: 上位 3 件に入るかだけで測る（先行する長い候補で予算が尽き、表示されない gold を拾えたと数える）
- 採用: unit 単位で依頼を作る前に分け、tune で固定して held-out を 1 回だけ測る。棄却: positive の対象だけを後から半分に分ける（誤候補を調整した方式を独立に確かめられず、同じ unit が両側に入る）
- 採用: B2 は `searchUnits` の公開された結果を絞る。棄却: FTS の rank の閾値で切る（`searchUnits` は rank を返さず、語の一致数で並べる）
- 採用: alias の一致を語の境界版と語分割版の 2 つで比べる。棄却: 今の語の境界だけ（日本語の文中の語に当たらず、alias という信号を過小に評価する）
- 採用: 合成の依頼を Codex と Claude が半分ずつ書き、alias と検索結果を見せない。棄却: positive を Codex、negative を Claude に固定する（書き手の文体とラベルが結び付く）。棄却: alias を見せて書く（alias の語が漏れて B1 が過大になる）
- 採用: 衝突の集合で再現率を数え、関連の集合と分ける。棄却: 関連する記録を拾えば成功とする（同じ話題の別記録だけでも成功になり、#260 の目的を測れない）
- 採用: 未達は「今回の方式では進めない」、標本不足は「保留」。棄却: 未達なら #260 を不採用にする（測ったのは一部の方式だけで、持ち主の決定にも反する）
