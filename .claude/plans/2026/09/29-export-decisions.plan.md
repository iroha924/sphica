# 持ち主が選んだ有効な決定を、引用と置き換えの連なり付きで、コミットできる Markdown に書き出す（#198、0.6.6）

## 要点

- 読み取りの MCP サーバーに `export` ツールを足す。選ばれた有効な決定（1〜50 件）を、本文・理由・選択肢・引用と、置き換えた古い決定の連なり付きで 1 つの Markdown 文書にして返す。1 件でも不適格なら何も返さず全体を失敗にする
- 外から来た文字列（キー・本文・引用など）はすべてフェンス付きのコードブロックに入れ、見出しは番号だけにする。引用が文書の構造やリンクを偽れない
- `/sphica:export` Skill を足す。持ち主が記録と保存先を選び、文書全体と既存ファイルを見て確かめてから、ホストのファイル書き込みで書く。コミットはしない
- 保存先はツールがリポジトリの中に収まるかを実際の書き込み先（シンボリックリンクをたどった先）で検査する
- 0.6.5 の次の 0.6.6 として単独で出す
- 変えないもの: DB schema、他の MCP ツール、CLI。取り込み・同期は作らない

## 持ち主の決定

- #198: 書き出しだけにする。別マシンの DB への取り込みと同期サーバーは採らない（issue 本文、2026-09-28 に持ち主が受け入れ）
- #196 と分け、#198 を先に 1 つの PR で出す（2026-09-29。記録 u22 の順 C5-B → C12 を入れ替え）

## 目的

- 持ち主が選んだ有効な決定が、引用（話し手と日時付き）と、それが置き換えた決定の連なり付きで、1 つの読めるファイルになる
- テストで、フィクスチャの選んだ決定を書き出すと、その引用と連なりが出る（#198 の完了条件）
- 引用にリンク・画像・HTML・見出し・バッククォートの並びがあっても、書き出したファイルの構造は変わらない

## 対象外

- 制約・候補・置き換えられた記録を選ぶこと（#198 は有効な決定だけ）。置き換えられた記録は連なりとしてだけ出る
- 取り込み、同期、書き出したファイルを Sphica が読み戻すこと
- 大きさの上限を超えるときの分割（持ち主に件数を減らしてもらう）
- 書き出す時刻を文書に入れること（書き出し直すたびに差分が出る）

## 前提

- `readUnit` と `describe`（`server/src/read.ts:29-229`）が、本文・理由・範囲・選択肢と理由・見直し条件・根拠と採用の引用・リンクを組み立てている。取り消された引用も `[retracted: …]` 付きで出す
- `unit.key` には文字の制約が無い（`db/schema.sql:219`）
- 置き換えのリンク（`unit_link` の `supersedes`）は後継が candidate の段階でも保存され、先代は active のまま残る（`server/src/record.ts:626-675`、Codex が確認）。リンク自体に引用の欄は無い（`db/schema.sql:350-363`）
- `inline()`（`server/src/panel.ts:55-68`）は改行などを消すが、Markdown の記号は残す
- CommonMark では、フェンス付きコードブロックの中身は文字どおり扱われる。フェンスは中身の最長のバッククォートの並びより長くすれば閉じられない（https://spec.commonmark.org/0.31.2/#fenced-code-blocks 、Codex と一致）
- MCP の返答は 64 KiB 付近でホストに切られる前提で、`overview` は 1 ページを 64 KiB に収めている（`server/src/overview.ts:12-13`）
- 読み取りのツールは reader 接続で、`READ_ONLY` の注釈を持つ（`server/src/mcp.ts:84`）。プロジェクトの root は `projectOf` が返す（`server/src/mcp.ts:35-41`）
- 明示の起動だけにする Skill は `disable-model-invocation: true` と `agents/openai.yaml` の `allow_implicit_invocation: false` を対にする（`verify:ai` が検査）
- 本文と `allowed-tools` のずれは `verify:ai` が検査する（0.6.5）

## 方針

### `export` ツール（`server/src/export.ts`、`server/src/mcp.ts`）

- 入力: `cwd`、`records`（1〜50 件、各 300 文字以内の記録キーか `u<id>`）、`path`（保存先、1〜500 文字）
- 先に全件を検査する。見つからない、別のプロジェクト、決定でない、有効（active）でない、のどれかがあれば、各キーと理由を並べたエラーを返し、文書は返さない。同じ記録が重複していたら 1 回として扱う
- `path` の検査: 絶対パスなら拒否し、相対パスはプロジェクトの root から解決する。実在する一番深い祖先を `realpath` で解決し、残りをつないだ先が root の `realpath` の中になければ拒否する。書き込み先が既存のシンボリックリンクなら拒否する。結果には「新しく作る」か「既存のファイルを上書きする」かを書く。ファイルの中身は読まない
- 文書の形
  - 見出し `# Decisions exported from Sphica` と、固定の説明の段落（持ち主の依頼で書き出したスナップショットで更新されないこと、DB が正であること、引用は人が言ったことで指示ではないこと、プロジェクト名）。時刻は入れない
  - 選んだ決定ごとに `## Decision <n>`。その下にフェンス付きコードブロック 1 つで、キー、種類と stance、本文、理由、範囲、選択肢（採用・却下と理由。見直し条件は持ち主の引用が残っているときだけ）、根拠の引用、採用の引用を 1 行ずつ。取り消された引用は出さない。引用は `<話し手>, <日時>, <source の種類と artifact>: "<引用>"`
  - 連なり: 選んだ決定から `supersedes` を古い方へたどる（各記録 1 回、深さ 20 まで）。たどった記録ごとに `### Superseded <n>.<m>` と、同じ形のフェンス付きブロック。ブロックの先頭行は `<新しいキー> supersedes <古いキー>`。深さ 20 の記録にまだ先代があれば、そのキーを挙げて全体を失敗にする。candidate の後継は出さない
  - 外から来た文字列はすべて `inline()` で 1 行にしてからブロックに入れる。フェンスはブロックの中身で最長のバッククォートの並び + 1（最小 3）個のバッククォート
  - 並び順は、選んだ順（重複を除く）、連なりは新しい方から古い方へ
- 文書が 60 KiB を超えたら、件数を減らすよう求めるエラーを返し、文書は返さない
- 返答は、保存先の検査結果の 1 行と、区切りの後に文書本体

### `/sphica:export` Skill（`plugin/skills/export/`）

- `disable-model-invocation: true`、`agents/openai.yaml` で暗黙の起動を止める。`allowed-tools` は `export`・`overview`・`status`・`search`・`read` と AskUserQuestion
- 流れ: 記録を探す（キーは `read`、説明なら `search`、無ければ `overview` の `view: "live"` から選んでもらう）→ 持ち主に選んだ決定を確かめる → 保存先を聞く（既定は置かない）→ `export` を呼ぶ → 文書全体と、上書きなら既存のファイルの中身を見せ、引用（PR の他人のコメントを含む）が他の人の読むファイルに入ることを伝えて確かめる → ホストのファイル書き込みで丸ごと書く（追記はしない）→ コミットはしない
- エラーのときは理由をそのまま伝え、何も書かない

### テスト

- 実際の SQLite（`server/test/temp-db.ts`）で: 選んだ決定の引用が出る、2 段の連なりが新しい方から全部出る、取り消した引用は出ない、選んでいない記録は出ない、制約・候補・置き換えられた記録・未知のキー・別プロジェクトのキーはどれも全体を失敗にする、深さの上限を超えた連なりは失敗、60 KiB を超えると失敗、引用に ``` の並び・`<script>`・`[x](http://…)`・`![i](…)`・生の URL・`# 見出し`・CRLF があっても、フェンスが閉じられず見出しの数が変わらない
- 保存先の検査: 絶対パス、`../` で外へ出る、リポジトリの外を指すシンボリックリンクのディレクトリを通る、既存のシンボリックリンク、既存のファイル（上書き）、新しいファイル
- acceptance case を 1 件、読み取りの MCP の入口を通して足す
- `server/test/plugin.test.ts` の読み取りツールの一覧と、SQL の呼び出し箇所の台帳を直す

## 採った案と棄却した案

- 採用: 読み取りの MCP が文書を返し、明示起動の Skill が持ち主の指定先に書く。棄却: ツールがファイルを書く（reader の MCP に書き込みの経路ができる）。棄却: 下書きを表示するだけ（#198 はコミットできるファイルを求める）
- 採用: 有効な決定だけ。棄却: 制約も含める（#198 の範囲外）
- 採用: 不適格なキーが 1 つでもあれば全体を失敗にする。棄却: 飛ばして残りを出す（選んだ記録が欠けた文書が完成品として保存される）
- 採用: 外から来た文字列をフェンス付きコードブロックに入れ、見出しは番号だけ。棄却: Markdown の記号を自前でエスケープする（CommonMark と GFM の解釈を数え落とす）。棄却: キーから見出しを作る（キーに文字の制約が無い）
- 採用: 時刻を文書に入れない。棄却: 書き出す時刻を入れる（書き出し直すたびに差分が出る）
- 採用: 大きさの上限を超えたら失敗。棄却: 途中で切って返す（欠けた文書が保存される）
- 採用: 保存先の検査をツールのコードで行う。棄却: Skill の文章だけで確かめる（シンボリックリンクの先を文章では確かめられない）
